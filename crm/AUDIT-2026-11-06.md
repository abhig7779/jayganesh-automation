### Checked and OK
- **Auth on every route:** all module routes sit inside `auth` + `active`. The only public routes are `/login`, `/up`, the webhook, the two `signed` PDF links, `bill-fonts` (regex-locked) and `sanctum/csrf-cookie`.
- **Bills:** `bills.index` uses `visibleTo`. Show, done, status, print and pdf all use `InvoicePolicy::view`.
- **Technicians never see money:** `JobCardPolicy::seePrices`, Home `technician` layout, print `withPrices`, the `jobcards.products` gate, and no customer, bill, product or search permissions.
- **Cost price:** shown only with `reports.margins`. The cost and margin sorts are dropped for others, and the import only writes cost with `prices.manage` + `reports.margins`.
- **Marketing features:** offers, segments and audiences need `offers.manage`. Leads and asked-price need `leads.manage`.
- **Job card photos:** the photo must belong to the card (404 otherwise), then the policy is checked. The disk is private, files are re-encoded to JPEG, and `Content-Type` is forced.
- **Expense receipts:** branch check and `finance.view`. Uploads are checked by mimes and size and stored under a hashed name on the private disk.
- **Product import:** the token is regex-locked and the file path is scoped to the user id.
- **Webhook:** HMAC-SHA256 over the raw body with `hash_equals`, rejected when the secret is empty. The verify token is checked with `hash_equals`. CSRF is exempted only for `/webhooks/whatsapp`.
- **Signed links:** bill PDF lasts 7 days and quote PDF lasts `valid_until` + 60 days, both `signed` and throttled.
- **SQL:** no raw SQL with interpolated input. `orderByRaw` directions are whitelisted and `whereRaw` uses bindings.
- **XSS:** `{!! !!}` only in `products/partials/results` (built with `e()`), the error-digest mail (text-only, phone numbers masked) and the Vite tag. `SearchText::highlight` escapes. Offer and audience CSVs guard against formula injection.
- **Secrets:** no tokens or keys in tracked files or git history. The only tracked env files are `.env.example`, `.env.production.example` and `automation/.env.example`, all with empty values. `.env`, `*.sqlite` and `bootstrap/cache/*` are ignored. The WhatsApp token lives only in `.env` and config (plaintext, the normal Laravel practice; it isn't kept in the `settings` table). Only yes/no flags reach views. No `Log::` calls with phones or tokens.
- **Money:** all paise integers. The GST maths use integers (basis points, half-up, largest-remainder split, odd paisa alternates CGST/SGST, round-off kept as its own line). - **Indexes:** the common filters are covered: `invoices(created_by, created_at)`, `(status, created_at)`, `(customer_id, status)`, `follow_ups(assigned_to, status, due_on)`, `stock_moves(product_id, created_at)`, `message_log` morphs and `wa_message_id`.

HSTS, `X-Frame-Options: DENY`, `nosniff` and CSP are set. The queue runs from cron through `schedule:run` with `withoutOverlapping`, and jobs have tries and backoff.

## Details and fixes

### H1. Search leaks other staff's bills and quotes (High)
`SearchController.php:90` and `:107` query `Invoice` and `Quotation` with no visibility scope. A Sales user typing `JG-2627-` sees the number, customer and total of every bill. The link 403s, but the data is already on screen.
**Fix:** `$invoice::query()->visibleTo($user)->…` and `$quotation::query()->visibleTo($user)->…`. Add a role test that Sales' search returns only their own bills.

### H2. Spoofable client IP defeats rate limits (High)
`$middleware->trustProxies(at: '*')` trusts `X-Forwarded-For` from anyone. On MilesWeb shared hosting, PHP sits behind the host's own Apache/LiteSpeed, not a client-controlled proxy. An attacker can rotate the header to get a new `login|ip` key every 5 tries and a new `throttle:20,1` bucket each time, so a staff password can be brute-forced. The repo is public, so the login URL and scheme are known.
**Fix:**
- Trust only the real proxy: `trustProxies(at: ['127.0.0.1', '::1'])`, or MilesWeb's documented proxy range, or `env('TRUSTED_PROXIES')`.
- In `LoginController`, add a second limiter keyed on the login alone, for example `RateLimiter::tooManyAttempts('login:'.Str::lower($login), 10)` with a 15-minute decay.

### H3. Inline scripts and handlers blocked by CSP (High: screens break in production)

- Replace the `on*=` attributes with Alpine (`@change="$el.form.submit()"`, `@submit="confirm(…) || $event.preventDefault()"`).
- Add a CI grep that fails on `<script(?![^>]*nonce)` and ` on[a-z]+="` in `resources/views`.

### H4. Marketing can export finance data (High)
The `marketing` role has `reports.view` (`Permissions.php:51`). `ReportBuilder::available()` hides only `staff` and `pnl`. `reports.register` (`ReportController.php:47`) has no extra check, so Marketing can download the sales register (every bill's customer, mobile, GST and due) and the expense register, plus the GST and daily sales reports.
**Fix:**
- In `available()`, require `finance.view` for `gst` and `ca`, and `reports.all_staff` for `daily`.
- In `register()`, add `abort_unless($request->user()->can('finance.view'), 403)`.
- If Marketing only needs campaign results, drop `reports.view` from the role and add an offer-results page.

### M1. Customer history ignores bill ownership (Medium)
`CustomerHistory::bills()` and `quotations()` list every document of the customer to anyone with `customers.view` (Sales, Marketing).
**Fix:** apply `visibleTo($user)` and keep "N other bills" as a count. If the owner wants the counter to see full history, record that as a deliberate exception in CONTRACTS.md.

### M2. Payment receipt IDOR (Medium)
`receipt()` checks only `payments.collect || reports.all_staff`. Sales can walk `/payments/1..n/receipt` and see other customers' payments, the bills they paid and the balance.
**Fix:** `abort_unless($user->can('reports.all_staff') || $payment->received_by === $user->id, 403)`, or a `PaymentPolicy`.

### M3. WhatsApp resend/manual IDOR (Medium)
Any user with `invoices.create` can POST `/whatsapp/messages/{id}/resend` for any outgoing log. That includes marketing templates (a paid send, possibly to an opted-out number if `queueTemplate` doesn't re-check) and other staff's bill messages. `manual` opens `wa.me` with the other customer's number and message text.
**Fix:**
- Allow the action only when `related` is an `Invoice` the user can `view` (`Gate::authorize('view', $log->related)`) and the category is `utility`.
- Keep the role check for owner/admin.
- Re-check opt-out in `resend()`.

### M4. Collect payment double-submit (Medium)
There is no idempotency key and the button isn't disabled on submit. Two quick clicks on "₹2,000 of ₹5,000 due" make two payment rows, and the bill drops to ₹1,000 due.
**Fix:**
- Add a hidden `client_key` (UUID) with a unique index on `payments(branch_id, client_key)`, and return the existing payment on a duplicate, as bills already do with `draft_key`.
- Add `@submit="busy = true"` and `:disabled="busy"`.
- Apply the same pattern to expenses (L2).

### M5. WhatsApp env names don't match (Medium)
| `.env.production.example` | `config/whatsapp.php` |
|---|---|
| `WHATSAPP_ACCESS_TOKEN` | `WHATSAPP_TOKEN` |
| `WHATSAPP_BUSINESS_ACCOUNT_ID` | `WHATSAPP_WABA_ID` |
| `WHATSAPP_API_VERSION=v21.0` | `WHATSAPP_GRAPH_VERSION` (default v23.0) |

Following the production template leaves `isConfigured()` false, and the CRM stays in manual mode with no error.
**Fix:** rename the variables in `.env.production.example` to match the config (which `WHATSAPP-SETUP-STATUS.md` also uses), or read both names in the config.

### M6. Dev login routes: defence in depth (Medium)
Today `/dev/login-as` and `/dev/frame` are **not reachable outside `APP_ENV=local`**: every copy is wrapped in `if (app()->environment('local'))`, and `route:list` shows them only because this checkout is local. Route caching doesn't change that. `php artisan optimize` on the server builds the cache under the server's env, `bootstrap/cache` is git-ignored, and a cache built locally would fail anyway because `dev.frame` is named twice (`devtools-jobcards.php:32` / `devtools-products.php:29` vs `devtools-offers.php:37`).

The risks:
- `.env.example` ships `APP_ENV=local`. If someone copies the wrong file on the server, every visitor can sign in as Owner with one GET.
- `devtools-offers.php:15-20` creates a user with password `password` if none exists for the role.
- `devtools-quotations.php:16` redirects to an unchecked `to` (open redirect).

**Fix:**
- Keep one file, `routes/public/devtools.php`, and delete the six module copies.
- Guard it with `app()->isLocal() && config('app.dev_login') && in_array(request()->ip(), ['127.0.0.1', '::1'])`.
- Never create users there.
- Add a boot check in `AppServiceProvider` that throws if `isProduction()` is false while `APP_URL` contains `jayganeshcaraccessories.com`.

### M7. Per-request query overhead (Medium, shared hosting)
- `components/layouts/app.blade.php:42` calls `HomeData::followUpBadge()` on every page. It builds a full `followUpsToday()`: `Schema::hasTable`, a 6-row fetch with `customer`, and 3 counts.
- `Schema::has*` / `getColumnListing` appear 31 times. Examples:
  - `BillController.php:331-334,447-451`
  - `HomeData.php:603-625` (called by most sections)
  - `CustomerHistory`
  - `SearchController`

  On MySQL each one is an `information_schema` query.
- Owner Home runs about 35–45 queries.

**Fix:**
- Now that the modules are merged, delete the `class_exists`/`Schema` guards.
- Make the badge a single `count()` cached for 60 s per user.
- Cache Owner Home aggregates for 60 s.

### M8. Server trusts the client's unit price (Medium)
For a catalogue product, `unit_price_paise` from the request is used as-is (`InvoiceService.php:410`). The UI flag `can.editPrice` (`prices.manage`) is never enforced on the server. Sales can't exceed the bill-wide discount percentage, but can reprice single lines, for example moving price between items.
**Fix:** when `! $by->can('prices.manage')`, ignore `unit_price_paise` and use `$p->price_paise`. Keep discounts in `discount_paise` and `bill_discount_paise` only.

### M9. IGST and B2B GSTIN can't be billed (Medium)
`InvoiceService` reads `$data['place_of_supply']` and `$data['customer_gstin']`, but `StoreBillRequest::rules()` doesn't declare them, so `validated()` drops them. Every bill is intra-state with no buyer GSTIN.
**Fix:**
- Add `'place_of_supply' => ['nullable', 'regex:/^\d{2}$/']`.
- Add `'customer_gstin' => ['nullable', 'regex:/^\d{2}[A-Z]{5}\d{4}[A-Z][1-9A-Z]Z[0-9A-Z]$/']`.
- Default the place of supply to the GSTIN's first two digits.
